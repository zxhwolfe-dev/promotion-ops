# 平台经验与工程约束

以下保留原仓库的现场经验，但区分“曾经观察到”与“可靠的工程保证”。

## OSCHINA 编辑目标

原操作曾因 `ai-write` 前缀命中旧文编辑器，险些覆盖旧文。现在默认新任务标签，检查完整新建路径，已有草稿停下交人工；不用宽泛 URL 匹配选标签。HTML 插入前校验安全标签和属性，插入后回读，不能把任意网页 HTML 放进已登录站点。

## 腾讯云发布

原经验：未选文章来源、没有官方标签、按钮无效都可能造成静默失败。这些是检查点，不代表固定 CSS 永远有效。不要因为 locator 点击后没看到结果就追加 evaluate 点击；先检查永久链接和独立回读。多 Monaco 模型、多个按钮、标签结构不符时失败退出，不猜第一个。

## CSDN 与阿里云编辑器

CSDN 标题激活区需要真实点击，按钮用 locator 自动滚动，不用视口坐标。阿里 mditor 的隐藏 textarea 是镜像，选择可见正文编辑器。可见滑块/扫码出现时保留页面；隐藏节点的存在不能直接判断验证码。人工完成后仍要检查真实结果，不能承诺“自动完成发布”。

## Gmail

搜索 hash 和输入框都需要确认目标查询，读取前还必须看到结果或明确空结果。fallback 必须先清空旧查询。发送按钮、提示 toast、Ctrl+Enter 都不能替代“已发送”的独立回读。会话合并使新线程 ID 缺失时保守待核验，不把老邮件算作本次成功。

## Reddit 与 OSCHINA 评论

原经验中 Reddit 连发后个人主页没有新评论，隔约两小时后重试成功；这不能推导为固定两小时安全窗口，也不能证明第一次一定未写入。未找到结果应标 unknown，而不是立即重发。新评论须绑定身份、目标、完整正文和稳定 ID；评论总数增加既可能来自别人，也不能证明指定回复成功。

## 进程退出、并发与资料目录

不要在连接回调内调用 process.exit，也不要把发送/发布命令接在 head 等可能提前关闭输出的管道后。使用结构化输出重定向到私有文件，再单独查看；被强杀仍可能留锁，须人工检查。多个 CDP 客户端共享默认 context 和站点状态，不因标签不同就获得账号隔离。

正确的百度看板域名在原现场记录中是 ziyuan.baidu.com；旧域名故障不能等同登录失效。登录持久性因平台而异，先自查页面状态再要求人工重登。独立 Chrome profile 保留登录态，也意味着它应按凭据目录保护。
