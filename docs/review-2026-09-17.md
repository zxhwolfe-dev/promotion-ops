# promotion-ops 代码审查与加固记录

审查基线：`8ae61534ddb5f00f198e54a4e5ead117297ef566`（main 初始提交）。审查覆盖公共连接层、全部 15 个平台脚本、README、workflow 与 lessons。下文修复行号以本报告所在分支为准；完整可运行替换文件均在同一分支。不修改旧的 `urls-day4.txt` 运营输入。

## 结论

保留独立脚本架构是正确的，不需要引入 LangGraph、多 Agent、常驻任务服务或数据库。主要问题不是“缺少一套框架”，而是成功判定不充分、写请求结果未知时缺少防重发、共享浏览器缺少边界。`browser.close()` 在 CDP 连接中不是本次应该删掉的代码；独立临时 Chrome 的测试也验证了这一点。

## 按严重程度排序的问题与修改

### P1-1：百度 token 明文传输及进程参数暴露

原 `scripts/baidu-ziyuan/push-urls.js` 第 13–18 行使用 `curl` 参数拼接 HTTP URL。环境变量仅避免硬编码，不能保护网络传输和子进程参数；这里只能判断有暴露风险，不能认定 token 已被窃取。原版也没有 HTTP、业务错误、部分接收和超时校验。

修改位置：[lib/baidu.js 3–50 行](../lib/baidu.js#L3-L50)、[推送入口 1–15 行](../scripts/baidu-ziyuan/push-urls.js#L1-L15)。改为原生 HTTPS fetch、URLSearchParams、超时、禁止重定向、禁止 HTTP 降级，响应必须确认全部接收。完整替换入口可直接使用：

```js
'use strict';
const { run, requiredEnv, readText } = require('../../lib/ops');
const { writeOnce } = require('../../lib/state');
const { prepareURLs, pushURLs } = require('../../lib/baidu');
async function main(args = process.argv.slice(2)) {
  const token = requiredEnv('BAIDU_PUSH_TOKEN');
  const batch = prepareURLs(await readText(args[0]), process.env.BAIDU_SITE || 'https://aiworkstation.cn');
  return writeOnce({ kind: 'baidu.push', site: batch.site, urls: [...batch.urls].sort() }, async ({ submit }) => {
    const result = await submit(() => pushURLs({ ...batch, token }));
    return { status: 'verified', evidence: { kind: 'api_acceptance', ...result, indexed: 'not_verified' } };
  });
}
if (require.main === module) run(main);
module.exports = main;
```

本次没有携带真实 token 访问百度，HTTPS 支持、实际配额和生产返回格式仍需小批验收；失败必须停止而非降级明文。批次内去重和相同批次防重发不等于不同批次的逐 URL 全局去重。

### P1-2：写入成功与“点击完成”混淆

原 Gmail 按 Ctrl+Enter 后打印 sent；Reddit 仅打印个人主页前两条评论的前 40 字；OSCHINA 只打印评论数。阿里云、CSDN、OSCHINA 发文缺少失败条件下的非零退出，腾讯云只看成功弹窗。所有这些都不能独立证明本次预期写入。

修改位置：[Gmail 发送 14–30 行](../scripts/gmail/compose-send.js#L14-L30)、[Gmail 回读 47–71 行](../lib/gmail.js#L47-L71)、[评论证明 17–40 行](../lib/comments.js#L17-L40)、[文章回读 75–109 行](../lib/articles.js#L75-L109)。文章回读绑定永久链接、精确标题和首尾正文样本；这是目标内容存在性证据，尚未绑定本次请求返回的业务 ID，不能严格排除已有同内容文章，启用无人值守前需补齐平台响应关联；评论核验新 ID、作者、完整文本，Reddit 另核验目标帖及永久链接 ID；邮件回读精确线程 ID，收件人和正文必须在同一封邮件内。

新增代码区分：账号可见、公众可见、审核通过、接口接收、搜索收录、已发送、对方送达。前三者等更强结果没有对应证据时明确不作保证。Markdown 渲染只做简化文本归一化，复杂格式造成无法匹配时保守退出；不是全格式内容等价证明。

### P1-3：超时后重跑会造成重复邮件、评论或投稿

原版只有文档上的 STATUS 约定，没有可执行的提交前记账和重复保护。固定等几秒或隔两小时再次点击都不能解决“远端已写入、本地未收到确认”。

修改位置：[lib/state.js 57–94 行](../lib/state.js#L57-L94)。意图规范化并哈希；在首次可能导致发布的按钮/POST 之前持久化 `submitted`。成功须有独立 evidence；提交后异常标 `unknown` 或 `needs_human`，相同操作不自动重放。多步发布面板只执行同一轮的配置和最终确认，不补第二轮点击。最关键的执行顺序是：

```js
record.status = 'submitted';
record.submittedAt = new Date().toISOString();
await writeJSON(file, record);
submitted = true;
return action();
```

人工核验入口位于 [lib/state.js 97–117 行](../lib/state.js#L97-L117) 和 `scripts/ops/reconcile.js`，默认只读，修改需要显式确认和平台证据链接，不自动提交。其“人工核验”是操作者声明，不是工具自行查证。跨机器、多个状态目录、文件丢失、突然断电和绕开脚本的外部操作不在本地去重保证内。

### P1-4：共享 CDP 标签、异常清理和并发相互干扰

原 `lib/cdp.js` 第 7–22 行连接默认 context，并用 `find(reuse)` 获取旧标签或新建标签，最后不清理新建标签。各平台的宽泛域名 reuse 会命中正在使用的页面。多个连接仍共享 cookies、存储和平台账号；进程内 mutex 无法阻止多个独立 node 脚本。回调内 `process.exit()` 会跳过 finally，但这不意味着 OS 会永久保留死亡进程的 TCP 连接。

修改位置：[lib/cdp.js 6–70 行](../lib/cdp.js#L6-L70)、[文件锁 15–38 行](../lib/state.js#L15-L38)、[CLI 收口 30–41 行](../lib/ops.js#L30-L41)。同一回环端口使用共享文件锁；默认新任务标签，不抢前台；只关闭本任务创建的标签；人工/未知状态保留；正常返回和异常路径都断开 CDP。唯一允许的显式复用是完整 URL 的唯一匹配，旧式回调复用直接拒绝。清理失败记录警告，不遮盖原始业务错误或已取得的成功证据。

`process.exitCode` 替代强制退出；SIGKILL/默认信号终止仍可能留锁，不能声称所有退出情形都能运行 finally。长期人工页面不按固定 TTL 抢锁；遗留锁处理方式见 README。

### P1-5：已有草稿、HTML 与跳转目标缺少防护

原 CSDN/阿里云正文直接插入可能追加到恢复草稿；腾讯云只验证第一个 Monaco 模型长度超过 200，不能证明正文等于用户输入。OSCHINA 将未经校验的 HTML 插入登录态页面；评论入口接受外部 URL；相似页面和重定向都可能导致写错目标。

修改位置：[lib/articles.js 27–65 行](../lib/articles.js#L27-L65)、[URL/导航检查 58–93 行](../lib/ops.js#L58-L93)、四个平台发文入口。旧草稿一律停止，不先 Ctrl+A 擦除；正文回读与输入比较，Monaco 要求唯一模型。HTML 只接受有限基础标签/属性及 HTTPS 链接；读回文字必须完整，不接受“只插入了一部分”。URL 按协议、精确域名和用途路径校验，OSCHINA/CSDN 文章作者路径以及腾讯资料路径有额外检查。

URL 校验不能对抗受信任站点本身被入侵，也不构成完整浏览器沙箱。HTML 白名单会拒绝带 style/class 等属性的旧素材，需要先改为允许的基础 HTML；不能为兼容率撤销安全检查。

### P2-1：选择器和等待策略静默失败

原版大量 `.first()`、全页文本、屏幕 y 坐标和 evaluate `if (button) click()`。页面改版会无操作成功退出，甚至点错按钮；固定 7–20 秒延迟既慢又不能证明页面已经准备好。

修改位置：[lib/ops.js 68–118 行](../lib/ops.js#L68-L118)、[标签选择 67–73 行](../lib/articles.js#L67-L73)、平台入口。优先 role/label/placeholder + 精确文案；按显式候选表降级；所有候选要求唯一可见，多个匹配报错，不直接选第一个。OSCHINA 取消坐标点击；隐藏验证码不计入人工挑战；固定 sleep 改为有上限的只读条件探测。腾讯标签仍保留“已确认两个输入框”之后的局部索引，是待真实 DOM 回归的明确契约，不是假称完全消除了 CSS 依赖。

没有实际生产耗时对照，所以只能说删除了无条件等待，不能宣称快了多少倍。也没有虚构第三方提交 API 的 action/schema；后续获取经过脱敏的真实提交响应后，可增加“请求已发出 + HTTP/业务码 + ID + 独立回读”的更强信号，不能用任何 200 响应当成成功。

### P2-2：统计从正文误抓数值，覆盖范围描述不实

原快照固定几篇旧文，还有 dev.to 首页占位；整页第一个数字可能来自正文而非计数器。Gmail sweep 只读收件箱前 15 条却称全量；GSC/百度看板本来只输出页面片段，没有真正结构化指标。

修改位置：[lib/metrics.js 1–21 行](../lib/metrics.js#L1-L21)、[快照 11–48 行](../scripts/stats/daily-snapshot.js#L11-L48)、`config/targets.example.json`、`scripts/gmail/sweep.js`、GSC/百度看板入口。改为配置明确文章目标和局部指标选择器，含时间、URL、数字类型、缺失原因及缩写精度标志，原子保存 JSON。Gmail 标记实际查询和是否分页完整；未实现全邮箱遍历。GSC/百度摘录明确 `unavailable`，不把诊断输出包装成已完成的指标采集。

本次只建立了更诚实的统计契约，**不是补齐了所有平台指标**。多处指标选择器留空会得到 null，必须真实观察后配置。不能将 null 填 0，也不能抹去失败原因让日报显示全绿。

### P2-3：可变资料更新的输入与历史去重

原资料更新不验证参数或简介长度，空简介无法清空，提交后不回读。修改位置：[Tencent 资料 12–38 行](../scripts/tencent-cloud/update-profile.js#L12-L38)。验证昵称、简介最多 50 个 Unicode 字符和 HTTPS 网站；允许空简介；独立页面回读。`PROFILE_CHANGE_ID` 表示一次明确变更，重试沿用，新的变更换 ID，避免把历史 A→B→A 误当作已完成的同一次请求。不能自动生成新 ID 绕过未知状态。

### P2-4：依赖、秘密目录与回归缺失

原仓库没有 package.json、测试或 CI，`.gitignore` 只覆盖 .env 等少量文件。修改 `package.json`、`.env.example`、`.gitignore`、`.github/workflows/test.yml`、`tests/*.test.js`。固定 Playwright 版本，限制生产依赖，Actions 固定已核验提交 SHA；新增测试覆盖公共逻辑、协议行为和 DOM 证明。日志脱敏也保持 JSON 可解析，秘密的 JSON 转义形式不会漏掉。

本次没有联网 npm 安装及其生成的 lockfile；固定版本安装、lockfile 与真实平台集成验收仍属上线检查项。专用 profile 和 trace 与密码一样敏感；文件模式不能替代 Windows ACL、操作系统账号隔离、防火墙以及泄露后的凭据轮换。

## 实际验证记录

本地命令：`npm run check`，`PROMO_TEST_BROWSER=/usr/bin/chromium npm test`。

28 个 JavaScript 文件语法通过；Node test 共 50 项（含父测试），47 通过、0 失败、3 明确跳过。真实临时 Chrome 测试确认了 CDP 客户端断开不终止浏览器、第二个连接可继续使用、Cookie/已有标签保留、自建页正常与异常清理、人工页保留。DOM 测试覆盖重复按钮拒绝、隐藏/可见验证码、已有草稿、安全 HTML 与部分插入、指标不误抓正文、文章及邮件的证据范围。

三个导航型集成测试受当前环境 `ERR_BLOCKED_BY_ADMINISTRATOR` 限制，即使本地 route.fulfill 也不能导航，因此跳过，没有关闭或修改浏览器管理策略。纯 DOM 和 CDP 测试已真实执行。所用版本是 Node 22.16.0、Chromium 144.0.7559.96、环境自带 Playwright Core 1.57.0-beta-1764944708000；**不是 package.json 固定的 1.63.0 运行结果**。CI 配置会安装固定版本，实际是否通过必须查看对应 Actions，不能从本地结果推断。

没有连接操作者的 127.0.0.1:9234，没有访问真实登录资料，没有实际发送邮件/评论/文章，没有向百度发送 token。这些账号操作不是本次代码审查授权下的测试副作用。

## 合并前仍需完成

安装固定依赖，生成并审查 lockfile；检查 CI 的真实结果。用专用账号进行每个平台最小样本验收：当前身份、编辑器恢复草稿、文章来源/官方标签真实绑定、唯一发布按钮、验证码暂停、提交后独立回读和明确失败。需要发出真实内容的验收必须由操作者明确批准，不批量发布。Gmail 需确认分页结束信号和会话合并行为；OSCHINA 需确认评论容器/作者/ID 契约；文章需区分当前登录态可见与公众可见。

补齐统计局部选择器和 GSC/百度结构化采集及日期口径。验证百度 HTTPS 接口，不支持时停止而不降级。账号身份自动断言尚未覆盖所有中文平台；配置 UID 不等于验证登录身份。建议先审查分支，再逐平台启用，不直接替换正在工作的 main。
